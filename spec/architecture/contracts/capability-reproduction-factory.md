# Capability Reproduction Factory Contract

## Mission

When a necessary software capability cannot be embedded or exposed adequately by a permitted native integration, the Capability Reproduction Factory (CRF) rebuilds that bounded capability as an Epoch-native mini-app with top-tier, measurable quality.

The target is the engineering capability/workflow, not automatically the entire reference product. The reproduction may exceed the reference in agent access, integrated context, speed, accessibility, cost or reproducibility, but claims must be measured.

## Entry request

Record the desired engineering task, capability slice, why native embedding/integration is insufficient, reference/version, required behavior and quality, inputs/outputs/state/errors, interop/performance/UX needs, privacy/security classification, reconstruction profile, benchmark suite and rights status.

Evaluate approaches in this order unless evidence justifies another:
1. native embedding or supported plugin/SDK;
2. native adapter plus Application Environment;
3. compatible open-source, standards-based or licensed capability;
4. independently built behavioral implementation from approved specifications;
5. implementation-internal analysis/decompilation only when specifically authorized and reviewed.

## Factory stages

1. Scope the smallest valuable capability.
2. Run and record the rights/provenance gate.
3. Characterize reference behavior and representative edge/failure cases using approved sources.
4. Specify a provider-neutral behavior contract: inputs, outputs, state transitions, errors, units, constraints and performance.
5. Search and assess open-source, standard-based and licensed foundations.
6. Set independent implementation boundaries; use clean-room methods where required by the review.
7. Build a mini-app with first-class human UI, accessibility, keyboard/navigation, agent-readable state, typed operations, project context and provenance.
8. Run differential/conformance benchmarks against approved reference cases.
9. Run security, privacy, reliability and domain-specific engineering validation.
10. Package a versioned capability descriptor, tests, dependency/license inventory, rights decision, benchmark report, limitations, compatibility policy and rollback path.
11. Monitor reference-version drift, dependency vulnerabilities and regressions; requalify material changes.

## Mini-app bar

The result opens, activates, closes and restores through the generic Epoch workbench surface, like Browser/Terminal. It provides a real user-facing workflow and meaningful structured operations to the agent, under shared authorization. It must not introduce a second world, BOQ, lifecycle, verification or learning authority. It must work without the reference product remaining open unless it is explicitly an environment adapter.

## Rights gate

Approved source material may include public specifications, standards, lawful behavioral observations, compatible open-source code, licensed components and materials owned or specifically authorized by the requester. Decompilation/static analysis is not a default: require documented authority and review for the exact technique/use. Never bypass access controls or copy protected code, private datasets, proprietary assets or branding without required rights. Unclear rights block the request until resolved.

Each release includes the reference/product version, approved method/evidence register, component licenses/SBOM, public contract, test corpus provenance, benchmark results, supported tasks/versions, known limitations and rollback.

## Refusal / block conditions

Block implementation-internal inspection when permission is unclear, reproduction based on unlawfully obtained evidence, copying protected materials without rights, a missing benchmark for a top-tier claim, failed mandatory quality/safety checks, or inability to isolate untrusted code/data.

## Success

A user completes the targeted capability inside Epoch; the agent can read relevant structured state and operate it with permission; the stated task suite passes; and users can inspect provenance, quality evidence, version compatibility and limitations.
